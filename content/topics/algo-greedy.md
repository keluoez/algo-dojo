## 一句话理解

贪心的**算法思想**：面对选择时**不考虑长远、只取当前看似最优**，并且这个选择一旦做出不撤销。它代码最简单，但难点不在写、在**证明这个短视选择确实安全**。

## 核心思想

**为什么可以贪心**（面试要能讲出直觉证明）：

- **贪心选择性质**：存在一个全局最优解，它的第一步就包含当前的局部最优选择——即"先拿了再说"不吃亏。
- **最优子结构**：做完这个选择后，剩下的仍是同类型问题。

**区间调度（LC435）**：要保留尽可能多的互不相交区间，按**右端点**排序，每次选结束最早的——它给未来留下的空间最大；与已选冲突的区间全部跳过。

```python
def erase_overlap(intervals):
    intervals.sort(key=lambda x: x[1])
    end = float("-inf")
    keep = 0
    for left, right in intervals:
        if left >= end:          # 与上一个选中的不冲突
            keep += 1
            end = right
    return len(intervals) - keep
```

**跳跃游戏（LC55）**：维护"当前扫描范围内能跳到的最远位置 `farthest`"。每个位置都尝试扩展它；i 一旦超过 farthest 说明走到了不可达区域；farthest 覆盖末尾即成功。

**跳跃游戏 II（LC45）**：求最少跳跃次数。遍历到当前一跳的边界 `end` 时必须起跳，此时把边界更新为这一跳收集到的最远位置——等价于"每一跳都选了收益最大的落点"。

**分发糖果**：相邻评分高者糖更多，左右各扫一遍取约束的最大值，是"两遍贪心"的代表。

## 现实中的典型案例

- **找零**：人民币/美元币制下从大面额拿起到凑齐（但不是所有币制都成立！）。
- 任务排班：会议室预订、手术室排期，结束早的先安排。
- 霍夫曼编码：反复合并两个最小频率节点（贪心构造最短编码）。
- 网络 Dijkstra/Prim 每步选当前最近边、操作系统选最短作业优先。
- 库存里临期商品先发货（FEFO）。

## 什么时候用

- 问题具有"早结束早受益""当前最值不影响后续"的结构。
- 能通过交换论证：假设最优解第一步没这么选，交换后不会变差。
- 贪心证明没把握时，用 DP/回溯验证几个样例对比结果。

## 易错点

- 区间调度按右端点排，不是按左端点也不是按长度。
- 贪心失效反例要敏感：硬币 1/3/4 凑 6，贪心给 4+1+1 三枚，最优是 3+3 两枚。
- 跳跃游戏维护的是"最远可达"，不是"每步被迫跳最远"。
- 只说"感觉可以贪心"不算证明，面试要给出交换论证或反例排查。
