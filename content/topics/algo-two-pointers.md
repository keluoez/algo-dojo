## 一句话理解

双指针的**算法思想**：用两个指针代替嵌套循环，每轮移动都"不可逆地"排除一批不可能的答案，把 O(n²) 压到 O(n)。滑动窗口是它的特殊形态——维护一个区间，右扩左缩，窗口内的信息增量更新。

## 核心思想与模板

**1. 对撞指针**：左右两个指针分别从两端出发，利用**单调性/极值性质**决定缩哪一边（如有序数组找和、盛水容器）。每移动一步，一侧的可能性被永久排除。

**2. 快慢指针**：链表/数组中不同速度，见链表章节（中点、判环、原地去重）。

**3. 滑动窗口**：右指针负责"吃进"元素，窗口不满足约束时左指针负责"吐出"元素：

```python
def length_of_longest_substring(s):
    from collections import Counter
    window = Counter()
    left = 0
    best = 0
    for right, ch in enumerate(s):
        window[ch] += 1
        while window[ch] > 1:          # 窗口非法：有重复
            window[s[left]] -= 1
            left += 1                  # 左收缩直到重新合法
        best = max(best, right - left + 1)
    return best
```

**定长窗口**：窗口大小固定，右端进、左端出，每步检查一次。
**变长窗口**：上面的模板，关键问自己三个问题——何时扩、何时缩、何时更新答案。

## 现实中的典型案例

- 网络通信的**滑动窗口协议**（TCP）：窗口内的帧已发待确认，整体向前滑动。
- 实时数据流：统计"最近 60 秒内的独立用户数"。
- 风控：在连续刷卡记录中找"10 分钟内跨 3 个城市"的异常窗口。
- 日志分析找一段连续高错误率区间、基因序列找最长无某标记片段。

## 什么时候用

- 有序序列上找配对/极值，排除一侧后答案不受影响 → 对撞指针。
- 问题描述里出现"**连续**子数组/子串 + 最长/最短/个数" → 滑动窗口。
- 窗口状态能用计数器增量维护（加一个、减一个都 O(1)）时最划算。
- 子序列（不连续）问题不适合滑窗，通常靠 DP。

## 易错点

- 收缩条件要想清楚是 while 还是 if：要求窗口"重新合法"一般用 while。
- 更新答案的位置：最长问题通常在窗口合法后更新；最短问题在收缩时更新。
- 计数减到 0 的 key 不必删，但判断存在性时要看值而非 `in`。
- 滑动窗口要求元素移动方向单调，需要回头看的场景不适用。
