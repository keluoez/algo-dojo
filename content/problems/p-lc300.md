  from bisect import bisect_left

  def length_of_lis(nums: list[int]) -> int:
      tails = []
      for num in nums:
          pos = bisect_left(tails, num)
          if pos == len(tails):
              tails.append(num)
          else:
              tails[pos] = num
      return len(tails)

给定一个整数数组 `nums`，找到其中**最长严格递增子序列**的长度（子序列不要求连续，但不能改变相对顺序）。

**提示**：除了经典 O(n²) DP，还有一种"耐心排序"玩法：维护各长度递增子序列的最小结尾。为什么替换结尾不会改变答案长度？

--- 题解 ---

## 思路：贪心维护 tails + 二分

tails[k] = 长度为 k+1 的递增子序列中，**最小的结尾元素**。

逐个处理 num：二分找到 tails 中第一个 >= num 的位置（bisect_left 保证严格递增；允许非降则用 bisect_right）：

- 位置等于 tails 长度：num 比所有结尾都大，延长最长序列；
- 否则替换该位置结尾——结尾更小，对后续元素更"友好"，且 tails 长度不变。

tails 不还原真实子序列，但其长度就是 LIS 长度。

## 直觉：为什么替换合法

把每个元素看作扑克牌，tails 是若干"牌堆"顶：小牌总压在第一个顶 >= 它的堆上。牌堆数就是最长递增链长度。替换只优化堆顶、不增减堆，所以答案稳定，而未来能接的牌更多。

## 复杂度

- 时间 O(n log n)：每个元素一次二分。
- 空间 O(n)。

## 与 O(n²) DP 对比

f[i]=以 i 结尾的 LIS 长度，`f[i]=max(f[j])+1`（j<i 且 nums[j]<nums[i]），O(n²)。数据上万后差距明显，性能实测页可以直接对比两条曲线。若要求还原具体序列或统计 LIS 个数，则仍需 DP 版本。

## 易错点

- 严格递增用 bisect_left；非严格（最长非降）用 bisect_right，等号归属决定正确性。
- 误以为 tails 就是答案子序列——它只保证长度正确。
