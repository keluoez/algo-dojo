solution_code: |
  def ship_within_days(weights, days):
      def days_needed(cap):
          need, cur = 1, 0
          for w in weights:
              if cur + w > cap:      # 当天装不下，开新的一天
                  need += 1
                  cur = w
              else:
                  cur += w
          return need

      lo, hi = max(weights), sum(weights)
      while lo < hi:
          mid = (lo + hi) // 2
          if days_needed(mid) <= days:
              hi = mid               # mid 可行，尝试更小
          else:
              lo = mid + 1           # mid 不可行，必须更大
      return lo

物流公司的干线车队要在 `days` 天内把一批包裹全部运走。包裹必须**按 `weights` 给定的顺序**逐日装车（同一天内也按顺序连续装载，不能拆单、不能跳过），车队每天所有车合计运载能力为 `cap`（每天总重不得超过 `cap`）。

求能按时运完全部包裹的**最低日运力** `cap`。

**提示**：运力太小运不完，运力足够大一天全运走——"可行性随 cap 单调"。单调的东西就能二分：二分的不是数组下标，而是**答案本身**。别忘了 `days_needed(cap)` 怎么贪心地算。

--- 题解 ---

## 思路：二分答案 + 贪心验证

**答案具有单调性**：cap 越大，需要的天数只会更少。于是答案空间 `[max(weights), sum(weights)]` 本身就是一个"单调数组"，对它二分：

- **下界 `max(weights)`**：再大的车也得装得下单件最重的包裹；
- **上界 `sum(weights)`**：一天全运走，一定可行。

给定 cap，用贪心算"最少要几天"：顺序扫描，当天装不下就开新的一天（顺序固定时这显然是最优装载）。判定 `days_needed(cap) <= days` 收缩区间，`lo == hi` 即最低可行运力。

## 复杂度

- 时间 O(n log S)：S = sum - max，二分 O(log S) 次、每次验证 O(n)。
- 空间 O(1)。

## 易错点

- 二分的对象是**答案**不是下标：区间是候选运力值，`lo` 起点 must 是 `max(weights)` 而不是 1。
- 验证函数里"当天装不下就开新一天"的前提是**顺序不可打乱**；如果允许乱序装载，贪心不成立，问题也完全不同。
- `mid` 可行时收缩是 `hi = mid`（mid 可能就是答案），不可行才是 `lo = mid + 1`。
