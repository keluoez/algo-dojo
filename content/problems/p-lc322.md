  def coin_change(coins: list[int], amount: int) -> int:
      inf = amount + 1
      dp = [0] + [inf] * amount
      for coin in coins:
          for money in range(coin, amount + 1):
              dp[money] = min(dp[money], dp[money - coin] + 1)
      return -1 if dp[amount] == inf else dp[amount]

给定不同面额的硬币 `coins`（每一种硬币数量无限）和总金额 `amount`，编写函数计算**可以凑成总金额所需的最少硬币个数**；没有任何硬币组合能凑出返回 -1。

**提示**：为什么不能贪心（先拿最大面额）？DP 状态 dp[m] 表示什么？硬币可无限使用对应完全背包，遍历顺序和 0/1 背包有何不同？

--- 题解 ---

## 思路：完全背包求"恰好装满"的最小件数

dp[m] = 凑出金额 m 的最少硬币数，不可达标记为 amount+1（任何合法方案硬币数都不超过 amount）。

转移：对每种硬币 coin，`dp[m] = min(dp[m], dp[m-coin]+1)`，金额**从小到大**遍历——小金额先被该硬币更新，大金额就能重复使用同一枚硬币，这正是"完全背包"；0/1 背包则要从大到小避免重复选取。

## 为什么贪心在这里失效

硬币体系 [1,3,4]、金额 6：贪心 4+1+1 = 3 枚，最优 3+3 = 2 枚。贪心只在硬币面额满足规范倍数性质（如真实硬币 1/5/10）时正确；DP 不依赖面额结构，对任意体系成立。

## 复杂度

- 时间 O(k · amount)，k 为硬币种数。
- 空间 O(amount)。

## 背包问题导航

- 0/1 背包（每件最多一次）：容量倒序；
- 完全背包（每件无限）：容量正序；
- 问方案数用加法、问最值用 min/max、问可行性用布尔。

## 易错点

- 哨兵要比任何真解都大（amount+1），否则 min 会选到哨兵。
- amount=0 返回 0（不需要硬币），不是 -1。
